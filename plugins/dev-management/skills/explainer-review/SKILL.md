# Explainer Review — 出力前の読み手レビュー

解説文を出す前に、**3つの役を順に演じて**、読み手が止まる箇所を潰してから出す。
文章の書き方そのものは `explainer-style`・`explainer-citation`・`explainer-structure` が定義する。この Skill は **書き終えた後の検査と書き直しの手続き**だけを定義する。

## なぜ役を分けるか

書いた本人が読み返すと、書いた推論が頭に残っているので、文書に書かれていない情報で空白を埋めてしまい、読み手が止まる箇所を見落とす。
だから、**読む役（止まるだけ）→ 診断する役（直す場所を決めるだけ）→ 書く役（書き直すだけ）** に分け、各役が見てよいものを絞る。

この Skill は1つの会話の中で3役を演じるので、役の分離は**機構ではなく規律**でしか守れない。下の「役ごとに見ないもの」を、そのつもりで守る。

## いつ・どこまで回すか

| 出力 | 回し方 |
|---|---|
| チャット内の解説（数段落） | 1周。読み手パスで「止まる」が0なら書き直さずそのまま出す |
| ファイル出力（3つまで）・長い解説・図を含む解説 | 最大2周。2周目の読み手は、書き直した節だけでなく**冒頭から最後の変更箇所まで**を読む（前段で足した前提が見えないと誤検出する） |
| 指摘への対応（`explainer-style` 原則9） | 書き直した本文に対して1周 |

**周回上限は2。** 2周しても残った「止まる」は、出力の末尾に「未解決」として1〜3行で明記する。隠さない。

## 過程は本文に混ぜない

読者が欲しいのは読みやすい本文であって、レビューの記録ではない。

- 3役の作業は **拡張思考（thinking）の中で行う**。使えない場合は、本文の後に `---` で区切って「レビュー記録」を5行以内で置く（止まりの件数と直した箇所だけ）
- 「読み手として読むと〜」「診断の結果〜」のような文を本文に書かない
- 「レビューを見せて」と言われたときだけ、止まり・診断の全文を出す

## 1. 読み手パス

**役**: 下書きを、**Python は読めるが、扱っている周辺技術には不慣れな読者**として読む。**止まった箇所を列挙するだけ**で、直し方は考えない。

**見てよいもの**: 下書き本文と、この会話でこれまでに読者へ説明済みの内容だけ。
**見ないもの**: 一次情報（公式ドキュメント・原典・リポジトリ）の中身と、自分がそれを読んで知っていること。知っている前提で読むと、書かれていない前提を自分で補って読めてしまい、読者が止まる箇所を見落とす。「たぶんこういう意味だろう」と補完できた箇所こそ止まりとして挙げる。

**姿勢**: デフォルト拒否。承認する理由ではなく、止まる理由を探す。「まあ分かる」は止まり。

**止まりの書き方**（1件ずつ）:

- **箇所**: 止まった記述を前後ごと引用する（要約しない）
- **疑問**: 読者の口調の疑問文、または「〜というイメージ？」のような仮説の申告。1件1疑問
- **先に進めるか**: 止まる ／ 気になるが進める — 判定の問いは「この疑問を持ったまま次の節を読んだとき、次の節の主張を評価できるか」
- **根拠**: 1行（省くと何でも「止まる」になる）

書かないもの: 修正案、原因の推測、褒め言葉、分類名。

**何を見て止まるか**（手がかり。項目名は止まりに書かない）

1. **供給**: この語・記号・工程は、ここまでで説明されたか
2. **順序**: 未知の語で始まっていないか。後ろの節の内容を前提にしていないか
3. **量**: 1節に新しい概念がいくつ出るか
4. **像**: 「何をしているところか」が動作として浮かぶか。図は本文の分岐・累積・順序を描いているか
5. **言い直し**: 難しい表現の直後に平易な言い直しがあるか。主語・指示語は埋まっているか
6. **例**: 抽象的な主張に、具体例（動く最小例、実際のコマンド）が付いているか。数式は小さい数値例があるか
7. **語**: 同じ語が2つのものを指していないか。references/typical.md の典型例や、references/past_stops.md で過去に詰まった語と違う使い方をしていないか。定訳が消えていないか
8. **接続**: 定義から帰結へ、主張から論拠へ、間が飛んでいないか
9. **正確性**: 自分の知識と矛盾する断定はないか。文書の別の箇所（定義・表・別の節）と食い違っていないか
10. **身分**: この断定は一次情報が書いていることか、書き手が補ったことか
11. **形**: 問いの形の見出し、否定形の回答文、1文に複数の主張はないか

**過去に読み手が止まった実例**は [references/past_stops.md](references/past_stops.md) にある。書き方が原因で止まった箇所を集めたもので、題材は別分野のものが混ざるが、止まっているのは書き方なのでそのまま使える。

ファイル出力・長い解説のときは読んでから読み手パスに入る。チャット内の短い解説では任意。チェックリストではなく、止まり方の実例として使う。

## 2. 診断パス

**役**: 各止まりを軸と型に振り分け、**どこを・どの型で直すか**を決める。本文は書かない。

**見てよいもの**: 止まりの一覧、下書き全体、一次情報（この会話で参照しているもの）。

**止まった場所と直す場所は一致しない。** 後半で止まった原因が冒頭の前提の欠落、ということが起きる。疑問文は症状であり、直す場所は診断が決める。

**分類**（どの型か迷ったら「その止まりを消すために書き手が何をすることになるか」で決める）

| 軸 | 型 | 対処 |
|---|---|---|
| 知識 — 読み手が持っていないものを文書が供給していない | 概念未供給 | 前段に足す |
| | ペース（一度に新概念が多すぎる） | 足さない。**並べ直す**。1節に新概念1つ |
| | 順序（未知から始まっている） | 既知から未知へ並べ直す |
| 表現 — 供給はしているが受け取れる形でない | 像がない | 「何をしているところか」を動作で書く、図にする（図は分岐・累積・順序を描く） |
| | 言語化不足 | 術語は残し、直後に平易な言い直しを併記。主語・指示語を埋める |
| | 例示がない | 具体例、対比表、小さい数値例 |
| | 語の選択 | 同じ語が2つの実体を指すなら語を分ける（分けられなければ「どちらの問いに答える語か」を書く）。既知の意味に吸着する語は正しい像を先に立てる。定訳を消さない、実装の話は型で書く。**言い直しの併記では消えない** |
| | 論理の接続 | 定義→帰結、主張→論拠の間に事実を挟む。根拠・条件・理由を同じ階層に並べない |
| 正確性 — 文書が間違っている | 言いすぎ | 主張の範囲を限定する。一次情報の表現に戻す |
| | 誤り | 一次情報で照合して直す |
| | 文書内の不整合 | 一方に統一するか、成立範囲の違いを書く |
| | 身分の偽り | 書き手が補ったことを一次情報の主張として書いている。身分を明示させる（下記） |
| 一次情報の穴 — 文書の欠陥ではない | （型なし） | 「つまずきポイント」節へ ⚠️ 付きで移す。**滑らかにしない**。書き手が補った論拠・先回りの不足は表現軸で扱う |
| 形 | （診断では型にしない） | 書き手パスの「回答の形」の確認で扱う |

**一次情報が答えていないこと**は本文で埋めない。該当箇所に「⚠️ 公式ドキュメントでは明示されていない」と1行で書くか、「つまずきポイント」節に ⚠️ 付きで移す。

**判定のルール**

- 同じ欠落から出た複数の止まりは、1件の直しに束ねる
- 表現軸の直し方には必ず **「術語は残す」** と書く（「平易に」とだけ決めると術語が消える）
- 論文の穴を例示や論拠を足してもっともらしく埋めない（同語反復ができる）
- **正確性軸は、一次情報の該当箇所（節・見出し・API 名・行）を開いて原文を引けたときだけ**使う。引けないなら正確性軸に分類しない。診断は一次情報と照合する唯一の役なので、ここで記憶に頼ると誰も気づけない

**断定の「身分」を見る**

正確性の判定は「内容が正しいか」だけでは足りない。その断定が誰のものとして書かれているかで分かれる。

| | 中身 | 診断の扱い |
|---|---|---|
| **(a) 一次情報が書いていること** | 出典を付けて断定している | 一次情報と照合する。違えば「誤り」、範囲が広がっていれば「言いすぎ」 |
| **(b) 一次情報は書いていないが、一次情報の記述から導けること** | 書き手の推論。根拠は文書内にある | **一次情報の主張として書いていれば「身分の偽り」。** 書き手の推論と明示してあり、根拠が本文内にあるなら正確性軸に入れない（根拠の提示が足りないだけなら表現軸「論理の接続」） |
| **(c) 一次情報からは決まらないこと** | `⚠️ 要検証` が付いている、または「つまずきポイント」節にある | 正確性軸に入れない。ただし下記の検査を行う |

`⚠️ 要検証` が付いているのに実は一次情報に書いてあるなら確認漏れ（「誤り」として直す）。`⚠️` も推論の明示もないのに一次情報に根拠がないなら「身分の偽り」。

**合格**: 文書起因（知識軸＋表現軸＋正確性軸）が0件。論文の穴は残ってよい。合格なら書き手パスに進まず出力する。

## 3. 書き手パス

**役**: 診断が決めた「どこを・どの型で」だけを受けて、影響する節を**丸ごと書き直す**。

**見ないもの**: 読み手パスの疑問文そのもの。疑問文を見ながら書くと、その疑問に答える節を足すことになり、文書が論理の順ではなく質問の来た順に組み上がる。書き直しは診断の「直す場所・直し方」だけを見て行う。

**手続き**（順番を飛ばさない）

1. 影響する節の見出し（または段落の役割）を並べる
2. 論理の順序を再設計し、新しい並びを先に決める
3. 影響する節を丸ごと書き直す
4. `explainer-style` の「文章スタイル チェック」と、一次資料を根拠にしているなら `explainer-citation` の「出典 チェック」を通す

**禁止**

- 疑問文を見出しにする
- 該当箇所の後ろに補足として足す（局所追記。これをやるなら書き直しの意味がない）
- 術語を消す（診断が「平易に」と言っていても、術語は残して直後に言い直しを併記する）
- 診断が決めていない箇所を「ついでに」直す（差分が追えなくなる）
- 一次情報が書いていないことを、もっともらしく補う（一次情報が答えていないことは ⚠️ を付けて「つまずきポイント」節へ移す）

**書き直しの後、回答の形が残っていないかを見る。** 1つの会話で3役を演じているので、疑問文への回答の痕跡が特に残りやすい。

- 誤読を打ち消す否定形（「〜でも〜でもない」）→ 肯定形で「何であるか」だけを書く
- 質問を言い換えた見出し・リード文（「ここで押さえておきたいのは」）→ 対象の名前を見出しにして地の文で述べる
- 尋ねられた一点だけを太字にする強調 → その語の動作の記述から書き始める

判定は「尋ねられなかった場合にも同じ文を書くか」。
